## Product in one paragraph
Miletag turns a race into wall art. Free: live editor and preview, drag the GPX route, photo or one of 5 map backgrounds, 1–6 runners on designs that support it, social-size export with a small "made with miletag" watermark (virality). Paid (physical only): print, frame, Deep Frame with optional 3D raised route and/or one medal slot, delivered. Malaysia first (MYR), global later. iOS + Android + Web from one Expo codebase.

## Locked decisions (don't re-litigate)
- **No subscription. No paid digital products.** Free export is social sizes only (IG Story 1080×1920, IG Post 1080×1350, phone wallpaper); print-res files never leave the server. So no app-store IAP.
- **Sizes:** A4, A3, A2 on 200 gsm premium matte fine-art paper, fade-resistant (pigment) inks.
- **A2 is unframed print only:** no Framed, no Deep Frame, so no medal or 3D on A2.
- **Formats:** Print / Framed / Deep Frame (~3–4 cm gap, a.k.a. shadow box). 3D route and medal slot need the Deep Frame.
- **Medal:** exactly one slot, one medal per frame. Customer inserts their own medal (we never take custody). Kept on A4 (max ~85 mm), A3 (~110 mm).
- **3D route:** flat raised line printed from the user's GPX on a **Bambu Lab P2S** (route bbox cap ~240 mm on A3, ~170 mm on A4). Colours: white, black, signal orange, neon yellow, silver, gold. Paid add-on.
- **Production:** 2D prints by a **third-party fine-art print shop**; Miletag does 3D printing, framing/assembly, QC, shipping in-house. Every print comes back to Miletag before shipping.
- **Volume:** a few orders a week at launch. Production Console is a lite internal web tool.
- **Runners:** user picks 1–6 first; gallery shows only designs that support that count. Medal designs can show 1–6 runners but still one medal slot; crews each order their own copy via a **Crew Copy Link**, and **each copy highlights the buyer's own name** (locked).
- **Bahasa Malaysia:** shortly after launch, not v1. Keep strings i18n-ready.
- **Strava:** optional OAuth; GPX upload must work fully on its own.
- **Map data:** OpenStreetMap via MapLibre. Dev uses free OpenFreeMap tiles; production should self-host (set `EXPO_PUBLIC_MAP_TILES_URL`). Avoid Mapbox/Google for print.
- **App ID:** `app.miletag` (iOS bundle + Android package). Can't change after store publish; owner hasn't objected.
- **UI references:** SmoothUI (smoothui.dev, use its per-component "Copy Markdown" docs / `llms-full.txt`), Bencho (bencho.dev, prompts/code gated behind its free account, not accessible to us), Amicro (amicro.vercel.app blocks bots; GitHub repo `Subhan-code/Amicro--Micro-transitions-` is readable). They're web React + Tailwind + Motion, so port the motion to Reanimated, don't import them.

## What's built (as of this handoff)
- Expo SDK 57 + Expo Router app. Screens: home → runners (1–6) → designs (filtered) → editor → "Get it made" (size/format/frame/3D/medal + live price). `admin/` is a placeholder.
- `src/domain/catalog.ts`: all availability rules above + pricing placeholders. `design-document.ts`: the JSON every render uses (schemaVersion 4). `route/`: GPX parse, 200 m privacy trim, RDP simplify, projection, keeps `geo` lon/lat.
- Map backgrounds: `src/domain/map-styles.ts` (Graphite, Paper, Blueprint, Noir, Terrain w/ hillshade; water/parks/roads toggles). `src/components/map-canvas/` uses `@maplibre/maplibre-react-native` v11 on native and `maplibre-gl` v6 on web; route is a map line layer (geo-locked), camera saved on user gestures.
- Ported SmoothUI components: `animated-tabs.tsx` (segment), `animated-toggle.tsx`, `map-style-carousel.tsx` (coverflow).
- **Photo backgrounds (built):** `src/domain/import-photo.ts` (expo-image-picker, full-quality original + ≤2048 px preview via expo-image-manipulator), `src/domain/photo.ts` (crop model, `clampCrop`, `photoDpi`, `gradeDpi`, `photoSlotMm`). The Skia `route-canvas` draws the photo (cover-fit, drag/pinch crop, B&W, scrim) with a "Move photo / Move route" switch. `components/photo-quality.tsx` = DPI traffic light (PRD §7.2) on the editor and the size picker; red needs "Print it anyway" (`lowResAckDpi`, covers that DPI or better) or checkout is blocked. Schema v5.
- **Editor UI (built, Instagram Stories style):** `src/app/create/editor.tsx`, one non-scrolling screen (header hidden in `_layout`). **Full screen:** for full-bleed designs (Big Time, Editorial, Mono Tech, Duo) the photo/map canvas fills the whole window; the print area (`frame`, A-ratio, full width on a phone, centred) is laid out exactly as it prints and the bleed around it is dimmed (`BleedMask`). Photos cover the print area; a blurred, enlarged copy fills the rest of the screen. Paper designs (Poster Classic, unbuilt designs) fill the screen with the paper colour (`look.paper`). `RouteCanvas` takes `size` + `frame` (everything relative to the frame); `MapCanvas` takes `fitInsets` so auto-fit keeps the route inside the frame. Layouts render text-only (no canvas child, transparent, touch-through `box-none`) over the frame. All overlays are see-through: back + vertical `ToolRail` (icons with shadow; `tone` light/dark) top, translucent toolkit sheet at the bottom; with a tool open the frame shrinks to fit above it. Tools: Background, Adjust (photo) / Layers (map), Route, Edit text (mode), Runner, Magic wand (full-bleed photo), Quality (photo only). Next (bottom right) is never greyed out; it opens the tool that fixes what's missing.
- **Bencho components (MIT):** `src/components/bencho/` — `time-scrubber.web.tsx` (TimeScrubber) and `generate.web.tsx` (Generate) are the DOM originals (comments kept), CSS in `src/global.css`; Bencho's colour tokens are defined *locally* on `.tms`/`.gen` with theme.ts values, `--font-ui` → `--font-display`. Miletag additions are optional props that default to the original behaviour (TimeScrubber: `min/max`, `pxPerUnit`, `ticks`, `formatValue/formatTick`, `value/onChange`, `tone="glass"`; Generate: `src`, `label`, `onRequest`, `onDone`, `cover`). `time-scrubber.tsx` / `generate.tsx` are simple native stand-ins (−/+ stepper; plain pill, no animation) until ported to Reanimated. `lucide-react` is only imported by the .web file (kept out of the Android bundle). Generate's FLOWER points at our demo photo.
- **Editor rules (owner, repeated twice — do not break):** the preview is always full screen and NEVER shrinks, moves or resizes when a tool opens; NOTHING ever opens below the image; controls overlay the preview on a see-through blurred band (`Glass` tray); there are NO Done buttons anywhere — a tap anywhere outside the controls closes them (a full-screen tap-outside `Pressable`; in text mode it sits *under* the print layer so text stays tappable, and layout containers are `pointerEvents: 'box-none'` so taps on empty space reach it). Verified by the scratch test `notray.js` (print-frame rect identical for every tool, no "Done", tap-outside closes each tool) — rerun something like it after any editor change.
- **Editor controls:** `components/editor/glass.tsx` (`Glass`, `GlassButton`, `GlassSwatch`, `GlassRow`; backdrop blur on web, translucent tint on native). Background = Photo/Map/New photo icons (+ map style swatches); upload = Generate pill in the middle of the print area (only the pill takes touches), the photo forms in, then becomes the background. Adjust = Move photo / Move route / B&W + darken ruler (TimeScrubber 0–80 %). Layers = water/parks/roads. Route = Upload GPX + colour swatches. Wand = centred intro over a blurred screen, "Lift me out" runs it (first time only). Runner form only for designs without a layout. Text mode puts its controls at the TOP (ink dots, or the dial) because time/pace/distance live in the lower half; the rail hides while a dial is open.
- **Dials for time, pace, distance:** tapping those fields opens a TimeScrubber dial instead of the keyboard (`isDialField`). Time in seconds (1 px/s, starts from the GPX/sample time), distance in 0.01 km, pace in s/km (sets the finish time from the distance; pace isn't stored). Native still gets the −/+ stepper stand-in.
- **Direct text editing (built):** the Aa tool is a mode, not a sheet. Layouts wrap each text in `<Editable field=…>` (`components/posters/editable.tsx`; the wrapper is always there so layout never shifts). In text mode each shows a ✎ badge and the text itself is tappable; tapping either blanks the field (fresh start, blinking caret; `withSamples(doc, editField)` skips the sample for it) and focuses one hidden `TextInput` in the editor (only the keyboard appears; must be focused synchronously in the tap for mobile browsers) and typing updates the doc live. Fields: title, date, city, country, `location` ("City, Country" split at the first comma), distance, `name:i`, `bib:i`, `time:i`. Text-mode bottom bar = the design's recommended ink swatches straight on the poster (no tray). Next jumps straight into editing the first missing field. Overlay is touch-through except in text mode (`box-none`).
- **Magic wand (built for web; native not yet):** rail switch on full-bleed photo designs. `src/domain/lift-subject.web.ts` runs **MODNet** portrait matting (Apache-2.0, code and weights; ONNX from `Xenova/modnet` on Hugging Face, 8-bit `model_quantized.onnx`, 6.6 MB; matched the 25 MB fp32 on a side-by-side, re-check on long hair) through **ONNX Runtime Web** on the preview photo: shortest side 512, multiples of 32, normalised −1…1 → soft alpha matte → upscaled onto the photo with `destination-in` → transparent PNG blob URL in `background.cutout` (+ `enabled`). People only (no bikes/objects). ORT's `ort.wasm.bundle.min.mjs`, `ort-wasm-simd-threaded.mjs` + `.wasm` are copied to `public/onnx` (Metro can't bundle it; loaded with `new Function('url','return import(url)')`, single thread since the site isn't cross-origin isolated). Model still loads from Hugging Face (TODO self-host). `RouteCanvas` draws the cutout in a top Skia canvas above its `between` layer (the design text) with the photo's darken/B&W via a colour matrix. **Native:** `lift-subject.ts` throws `LiftUnavailableError`; needs a native module (Apple Vision foreground mask iOS 17+, ML Kit subject segmentation Android) or MODNet via onnxruntime-react-native. **Print:** the cutout is preview-res; the server print render must re-matte the original.
- **Background switching keeps both:** `doc.backgroundStash` holds the background not in use; `switchBackground()` swaps them, so a photo (crop, darken, B&W) or map view survives Photo ↔ Map. Schema v7.
- **Text colour:** `doc.ink`, chosen from the design's recommended `look.inks` (first = default): Poster Classic black/navy/brick/forest; photo designs white/cream/neon/black; Mono Tech neon/white/signal/cyan. ## Gotchas learned
- Reanimated + React Compiler lint: use `sv.get()` / `sv.set()`, not `.value`.
- maplibre-react-native pins `@maplibre/maplibre-gl-style-spec` 26.2.1; our direct dep is newer, so the native map casts the style (`as unknown as MapProps['mapStyle']`).
- maplibre-gl: import `{ Map as MapLibreMap, setWorkerUrl }`; worker URL must be `/maplibre/maplibre-gl-worker.mjs`.
- Skia on web loads via `WithSkiaWeb` (`route-canvas/index.web.tsx`).
- `eas init` writes the *resolved* config into app.json; check the diff (it added RECORD_AUDIO from expo-image-picker, now disabled via `microphonePermission: false`).
- Prettier: no config in repo. Match style with `--single-quote --print-width 120 --bracket-same-line --trailing-comma all --object-wrap collapse`, and only on files you changed.
- Static web export pre-renders pages in Node: anything that loads CanvasKit must skip rendering when `typeof window === 'undefined'` (see `route-canvas/index.web.tsx`).
- `eas deploy --prod` can create the deployment but leave production on the old one (seen once). After deploying, check the live entry bundle; if stale, run `npx eas-cli@latest deploy:alias --prod --id <deployment id> --non-interactive` and give it ~30 s (it has needed this twice).
- Never put the owner's email (or any personal data) in requests to outside services, e.g. a User-Agent header.
- Playwright: launch with `executablePath: '/opt/pw-browsers/chromium'`; never `playwright install`.
